// Specifica di esecuzione: descrive la sintassi e la sua traduzione nella VM.
// I bachi o le eccezioni nell'implementazione di ewcc non cambiano il
// significato qui definito.

programma= { codice ";" }
  **NULLA
blocco= codice | "{" { codice ";" } "}"
  **NULLA 
// ";" non appartiene mai all'istruzione: termina una frase e separa i codici
// contenuti in un blocco. Anche un costrutto terminato da "}" viene seguito
// da ";" quando costituisce una frase del programma o del blocco esterno.
codice=[
  commento |
  datasetdecl |
  taskdecl |
  targetdecl |
  inblock |
  deleteblock |
  ifblock  |
  whileblock  |
  downwhile  |
  foreachblock  |
  forblock |
  asmline |
  vardecl |
  fundecl |
  calcexp]
commento= "'" [*] \n       'gestito da delperc

datasetdecl= dataset name datasetbody
// "context" non introduce una dichiarazione diversa: indica il dataset
// selezionato dal ciclo IN durante l'iterazione corrente.
datasetbody = "=" campidataset
campidataset= "{" [campodataset [, campodataset] ] "}"
campodataset = singlevar ["=" campidataset]
// Nessun prefisso di tipo: ogni campo contiene testo e la capacita' viene
// ampliata automaticamente dal backend quando serve.
// Durante il parsing non viene emessa alcuna variabile. Il compilatore legge
// integralmente il dataset in memoria, compresi i descrittori dei dataset
// annidati. Soltanto alla graffa finale emette tutte le celle del dataset
// corrente, contigue e in questo ordine:
  ** ADDSYMTABLE "name"
  ** PUSH "name"
  ** ADDSYMTABLE "name._url"
  ** PUSH "mysql://ewb"
  ** ADDSYMTABLE "name._user"
  ** PUSH "ewb"
  ** ADDSYMTABLE "name._password"
  ** PUSH "ewb"
  ** ADDSYMTABLE "name._status"
  ** PUSH "stopped"
  ** ADDSYMTABLE "name._orderby"
  ** PUSH ""
  ** ADDSYMTABLE "name.id"
  ** PUSH ""
  ** per ogni campo semplice, nell'ordine di dichiarazione:
  **   ADDSYMTABLE "name.campo"
  **   PUSH ""
// id e' implicito in ogni dataset e contiene la chiave primaria del record
// corrente. Un eventuale id nell'elenco esplicito dei campi viene ignorato
// durante l'emissione per non generare due celle con lo stesso nome.
// Un campo che contiene un dataset annidato non genera name.campo. Nel dataset
// esterno genera invece il riferimento name.id_campo, inizialmente vuoto:
  ** ADDSYMTABLE "name.id_campo"
  ** PUSH ""
// Terminata l'emissione del dataset corrente, il compilatore affronta in
// ricorsione ciascun descrittore annidato, nello stesso ordine. Ogni figlio
// viene quindi emesso come dataset distinto e forma a sua volta un blocco
// contiguo nello stack.
//
// Esempio:
//   dataset aaa = { bbb, ccc = { prova } }
// produce, prima di affrontare ccc:
  ** ADDSYMTABLE "aaa";           PUSH "aaa"
  ** ADDSYMTABLE "aaa._url";      PUSH "mysql://ewb"
  ** ADDSYMTABLE "aaa._user";     PUSH "ewb"
  ** ADDSYMTABLE "aaa._password"; PUSH "ewb"
  ** ADDSYMTABLE "aaa._status";   PUSH "stopped"
  ** ADDSYMTABLE "aaa._orderby";  PUSH ""
  ** ADDSYMTABLE "aaa.id";        PUSH ""
  ** ADDSYMTABLE "aaa.bbb";       PUSH ""
  ** ADDSYMTABLE "aaa.id_ccc";    PUSH ""
// e soltanto dopo:
  ** ADDSYMTABLE "ccc";           PUSH "ccc"
  ** ADDSYMTABLE "ccc._url";      PUSH "mysql://ewb"
  ** ADDSYMTABLE "ccc._user";     PUSH "ewb"
  ** ADDSYMTABLE "ccc._password"; PUSH "ewb"
  ** ADDSYMTABLE "ccc._status";   PUSH "stopped"
  ** ADDSYMTABLE "ccc._orderby";  PUSH ""
  ** ADDSYMTABLE "ccc.id";        PUSH ""
  ** ADDSYMTABLE "ccc.prova";     PUSH ""
// Le sei predefinite sono, nell'ordine: _url, _user, _password, _status,
// _orderby, id. _status non e' un campo SQL: la VM lo esclude sempre dallo
// schema; id corrisponde alla chiave primaria creata dal backend.
// Il vecchio parser inizializzava ncampi a 5 ma collocava _orderby in campi[5]
// ed emetteva soltanto gli indici minori di ncampi: questo errore non deve
// eliminare nuovamente la quinta predefinita.

taskdecl= task name "(" [varname {,varname}] ")"  "{" [codice] "}"
  ** stesso entrypoint e stesso frame dei parametri di fundecl
  ** all'entry point: TASK
  ** alla fine: ENDTASK; RET
  // Un task e' una funzione. Cambia il modo in cui viene avviata e il suo
  // stato pubblico ready/running/error.

targetdecl= target name "(" [varname {,varname}] ")" "{" [codice] "}"
  ** stesso entrypoint e stesso frame dei parametri di fundecl
  ** all'entry point: TARGET
  ** alla fine: ENDTARGET; RET
  // La chiamata del target implica riempire un form e saltarci.
  // TARGET registra lo stato ma non applica il lock globale per nome dei task:
  // browser diversi possono eseguire lo stesso target. STOP durante ASK o
  // SHOWFORM riporta _targets a stopped prima di sospendere la VM.
  ** i parametri sono valutati e passati per valore, come per una funzione




vardecl= var singlevar ["," singlevar]
singlevar = name [ "=" inexp ]
  ** se manca inexp: MOVA ""
  ** altrimenti valuta inexp                  ; A=valore iniziale
  ** ADDSYMTABLE "name"                       ; associa name alla SP corrente
  ** PUSHA
ifblock= if calcexp blocco [elseif calcexp blocco] { else blocco }
  ** valuta calcexp
  ** JZ NEXT
  ** valuta blocco
  ** JMP ENDIF
  ** NEXT:
  ** per ciascun elseif ripeti la stessa sequenza con una nuova NEXT
  ** se presente, valuta il blocco else
  ** ENDIF:

forblock= for (calcexp; calcexp; calcexp) blocco
  ** valuta inizializzazione
  ** COND:
  ** valuta condizione
  ** JZ ENDFOR
  ** JMP BODY
  ** STEP:
  ** valuta incremento
  ** JMP COND
  ** BODY:
  ** valuta blocco
  ** JMP STEP
  ** ENDFOR:

whileblock= while calcexp blocco
  ** STARTWHILE:
  ** valuta calcexp
  ** JZ ENDWHILE
  ** valuta blocco
  ** JMP STARTWHILE
  ** ENDWHILE:

downwhile= do blocco while calcexp
  ** STARTDO:
  ** valuta blocco
  ** valuta calcexp
  ** JNZ STARTDO

foreachblock= foreach (variabile,calcexp) { [codice] }
            | foreach (chiave,variabile,calcexp) { [codice] }
  ** valuta calcexp
  ** PUSHA                                      ; [source,...]
  ** PUSHA                                      ; [source,source,...]
  ** NUMKEY
  ** PUSHA                                      ; [count,source,...]
  ** PUSH 0                                     ; [pos,count,source,...]
  ** PUSH "dummy"                               ; [key,pos,count,source,...]
  // I quattro valori sono il frame anonimo del FOREACH. Non vengono aggiunti
  // alla symbol table. DECSP e INCSP permettono di raggiungerli senza
  // distruggerli e di sostituire il dummy con la chiave corrente.
  // [...] e' la parte attiva dello stack; i valori a sinistra della [
  // sono celle temporaneamente oltre SP. ... e' lo stack precedente.
  ** FOREACHCOND:
  ** DECSP 1                                   ; key,[pos,count,source,...]
  ** POPA                                      ; key,pos,[count,source,...] A=pos
  ** INCSP 2                                   ; [key,pos,count,source,...]
  ** PUSHA                                     ; [pos,key,pos,count,source,...]
  ** DECSP 3                                   ; pos,key,pos,[count,source,...]
  ** POPA                                      ; pos,key,pos,count,[source,...] A=count
  ** INCSP 4                                   ; [pos,key,pos,count,source,...]
  ** PUSHA                                     ; [count,pos,key,pos,count,source,...]
  ** LT
  ** JZ ENDFOREACH
  // Copia source e pos sopra il frame senza consumarli.
  ** DECSP 3                                   ; key,pos,count,[source,...]
  ** POPA                                      ; key,pos,count,source,[...] A=source
  ** INCSP 4                                   ; [key,pos,count,source,...]
  ** PUSHA                                     ; [source,key,pos,count,source,...]
  ** DECSP 2                                   ; source,key,[pos,count,source,...]
  ** POPA                                      ; source,key,pos,[count,source,...] A=pos
  ** INCSP 3                                   ; [source,key,pos,count,source,...]
  ** PUSHA                                     ; [pos,source,key,pos,count,source,...]
  ** KEYAT
  ** DECSP 1
  ** PUSHA                                     ; [key,pos,count,source,...]
                                                // sostituisce key/dummy
  ** se presente la variabile chiave:
  **   PUSH "chiave"
  **   PUSHA
  **   SETPATH 0
  // Copia source e key sopra il frame.
  ** DECSP 3                                   ; key,pos,count,[source,...]
  ** POPA                                      ; key,pos,count,source,[...] A=source
  ** INCSP 4                                   ; [key,pos,count,source,...]
  ** PUSHA                                     ; [source,key,pos,count,source,...]
  ** DECSP 1                                   ; source,[key,pos,count,source,...]
  ** POPA                                      ; source,key,[pos,count,source,...] A=key
  ** INCSP 2                                   ; [source,key,pos,count,source,...]
  ** PUSHA                                     ; [key,source,key,pos,count,source,...]
  ** GETELEM                                   ; A=valore
  ** PUSH "variabile"
  ** PUSHA
  ** SETPATH 0
  ** valuta blocco
  // Incrementa pos e sostituisce la sua cella senza toccare il resto.
  ** DECSP 1                                   ; key,[pos,count,source,...]
  ** POPA                                      ; key,pos,[count,source,...] A=pos
  ** INCSP 2                                   ; [key,pos,count,source,...]
  ** PUSHA
  ** PUSH 1
  ** SUM
  ** DECSP 2                                   ; key,pos,[count,source,...]
  ** PUSHA                                     ; key,[pos+1,count,source,...]
  ** INCSP 1                                   ; [key,pos+1,count,source,...]
  ** JMP FOREACHCOND
  ** ENDFOREACH:
  ** DECSP 4                                   ; key,pos,count,source,[...]
  // Se il FOREACH e' partito con stack vuoto, [...] e' precisamente [].
  // SP e' quindi tornato al valore che aveva prima del ciclo.
  // Source, posizione, conteggio e chiave restano nello stack tra i giri:
  // ASK li serializza e un ciclo annidato aggiunge un frame indipendente.
  // NUMKEY rende valida anche la chiave vuota: KEYAT non viene usata come
  // condizione di fine.
  // KEYAT(struttura,posizione) restituisce la chiave alla posizione indicata.
  // GETELEM(struttura,chiave) restituisce il valore senza richiedere il nome
  // di una variabile.
  ** assegna valore, oppure chiave e valore, dal primo all'ultimo
  ** visita chiavi numeriche e associative nell'ordine della struttura
  ** valuta la struttura una sola volta
  // Modificare nel corpo la stessa struttura attraversata ha comportamento
  // indefinito.
fundecl= sub token "(" [varname {"," varname}] ")" blocco
  ** JMP ENDFUNCTION
  ** entrypoint:
  // Durante la dichiarazione il compilatore registra nella propria tabella
  // name, arity ed entrypoint. Non crea una variabile nella VM: CALL contiene
  // direttamente l'entrypoint gia' noto.
  // CALL ha gia' creato [argN,...,arg1,return,...]. Ogni chiamata, anche
  // ricorsiva, ha celle distinte.
  ** DECSP arity                              ; argN,...,arg1,[return,...]
  ** per ciascun parametro, da arg1 ad argN:
  **   ADDSYMTABLE "varname"                  ; associa la cella oltre SP
  **   INCSP 1
  // Al termine dei parametri lo stack attivo e' nuovamente:
  // [argN,...,arg1,return,...]
  ** valuta blocco
  ** DELSYMTABLE arity
  ** DECSP arity                              ; argN,...,arg1,[return,...]
  ** RET
  ** ENDFUNCTION:
// Nome riservato per l'handler:
//   sub _onerror(error) blocco
// E' una normale funzione e puo' essere ridefinita in qualunque punto; quando
// la dichiarazione viene eseguita, il suo entrypoint sostituisce quello
// precedente tramite ONERROR. RAISE passa il testo dell'errore come unico
// parametro. Se nessun _onerror e' stato definito, la VM termina il codice.
// Una ridefinizione con corpo vuoto:
//   sub _onerror(error) { }
// non installa un handler che ignora l'errore: ripristina l'handler predefinito.
// Il compilatore emette PUSH ""; ONERROR; ONERROR con valore vuoto elimina
// l'entrypoint personalizzato. Il RAISE successivo termina quindi il codice.
// Quando un opcode esegue RAISE, consuma gli operandi come avrebbe fatto in
// caso di successo e lascia lo stack nella posizione prevista dall'opcode.
// Il risultato non prodotto non viene usato: la VM esegue una normale CALL
// _onerror(error), e il valore restituito dall'handler sostituisce A.
// RET dall'handler riprende dall'opcode immediatamente successivo a quello che
// ha eseguito RAISE. Non esiste un retry automatico del codice.
// Prima di chiamare _onerror, RAISE esegue DBROLLBACK su tutte le transazioni
// aperte, in ordine inverso. "Riprova da capo" riguarda un eventuale nuovo
// tentativo della transazione: il database e' tornato allo stato precedente
// al LOCK; non significa che la VM riavvii funzione, target o programma.
// L'handler deve quindi restituire un valore adatto al codice che prosegue.
// Se _onerror esegue a sua volta RAISE, non viene richiamato ricorsivamente:
// si applica l'handler predefinito e il codice termina.
//Sezione di sub-linguaggio assembler per la machina virtuale
asmline= "." ISTRUZIONE [numero | "stringa"] [' commento] "\n"

calcexp= assign "=" inexp | inexp         //    (no ll1 ! attento)
assign=variabile  { "[" calcexp "]" ]     //Array multidimensionali
  ** - a[3][2] = exp
  ** PUSH "a"                                  ; ["a",...]
  ** valuta 3; PUSHA                           ; [3,"a",...]
  ** valuta 2; PUSHA                           ; [2,3,"a",...]
  ** valuta inexp; PUSHA                       ; [valore,2,3,"a",...]
  ** SETPATH 2                                 ; [...] A resta il valore
// Se il target termina in ._orderby, inexp viene compilata con sql_mode=1.
// Le espressioni separate da virgola sono concatenate con ", ". Il backend
// aggiunge sempre id in coda una sola volta; se il frammento e' vuoto usa id.
// Eccezione: se l'intero lato destro e' il literal "", viene emesso MOVA ""
// senza attivare sql_mode. Serve a cancellare un ordinamento gia' impostato;
// non deve diventare il literal SQL ''.
inexp=exp  cfr inexp | exp
cfr = == | != | <= | >= | > | < | eq | neq | gt | ge | lt | le
  ** simbolici: GT, LT, EQ, NEQ, GE, LE; operando non numerico -> RAISE
  ** alfabetici: SGT, SLT, SEQ, SNEQ, SGE, SLE; confronto byte per byte
  // Traduzione normale:
  ** valuta EXP1
  ** PUSHA
  ** valuta EXP2
  ** PUSHA
  ** OP
  // Traduzione con sql_mode=1. DUMMY riserva una cella che viene sovrascritta
  // da EXP2; EXP1 resta temporaneamente oltre SP durante la sua valutazione.
  ** PUSH "("                                  ; (
  ** PUSH "DUMMY"                              ; DUMMY,(
  ** PUSHA                                     ; EXP1,DUMMY,(
  ** DECSP 2                                   ; (
  ** valuta EXP2
  ** PUSHA                                     ; EXP2,(
  ** INCSP 1                                   ; EXP1,EXP2,(
  ** PUSH " OP "                               ; OP,EXP1,EXP2,(
  ** CONCAT                                    ; A=EXP1 OP
  ** PUSHA
  ** CONCAT                                    ; A=EXP1 OP EXP2
  ** PUSHA
  ** CONCAT                                    ; A=(EXP1 OP EXP2
  ** PUSHA
  ** PUSH ")"
  ** CONCAT                                    ; A=(EXP1 OP EXP2)
  // OP SQL e' =, !=, <=, >=, > oppure <. Gli operatori alfabetici perdono
  // soltanto il prefisso S: il confronto viene comunque espresso in SQL.
  // Nei confronti simbolici, i valori esterni destinati a un operando numerico
  // vengono validati come numeri; una stringa parziale come "123A" provoca
  // RAISE. Identificatori e campi del dataset restano espressioni SQL.
  // SEQ/SNEQ accettano anche due array marcati e ne confrontano la struttura
  // canonica, ordine compreso. Misti e ordinamenti sugli array: RAISE.
exp=e . exp | e
  ** normale: valuta sinistra; PUSHA; valuta destra; PUSHA; CONCAT
  ** sql_mode: costruisce CONCAT(sinistra,destra)
e = t+e | t-e | t
  ** normale: SUM | SUB
  ** sql_mode: costruisce (sinistra + destra) | (sinistra - destra)
t = f*t | f/t | f%t | f
  ** normale: MUL | DIV | MOD
  ** sql_mode: costruisce (sinistra * destra), (sinistra / destra)
  **           oppure MOD(sinistra,destra)
  // DIV e MOD con divisore numericamente zero provocano RAISE.
  // MOD applica prima INT ai due operandi, troncandoli verso zero.
  // La conversione deve validare l'intero operando prima di troncare.
f= b\|f | b\|\|f | b
  ** normale: ORB | OR
  ** sql_mode: costruisce (sinistra | destra) | (sinistra OR destra)
b= k & b | k && b | k
  ** normale: ANDB | AND
  ** sql_mode: costruisce (sinistra & destra) | (sinistra AND destra)
  // | e &: bitwise interi della VM. || e &&: verita' EWB.
  // || e && valutano sempre entrambi gli operandi, da sinistra a destra.
// OR/AND logici devono usare la verita' EWB.
k= tok_var | ! inexp | !! inexp | numvalue | strvalue | (calcexp)
  ** !: NOT; sql_mode: NOT(espressione)
  ** !!: NOTB; sql_mode: ~(espressione)
tok_var= variabile[.variabile] [ "[" calcexp "]" ] | funzione | startparallel
variabile=token
** - a[3][2]
** PUSH "a"
** valuta 3; PUSHA
** valuta 2; PUSHA
** PUSH 2
** GETPATH                                    ; A=valore
// In sql_mode il nome viene prima sottoposto a JNCONTEXT:
** PUSH "nome"
** JNCONTEXT EXTERNAL
** MOVA "campo SQL senza prefisso"
** JMP ENDVARIABLE
** EXTERNAL:
** valuta normalmente la variabile
** PUSHA
** SQLQUOTE
** ENDVARIABLE:
funzione=token "(" [calcexp {,calcexp}] ")"
funzione = predef | token  "(" [inexp [,inexp]] ")"
// Le parentesi sono obbligatorie anche per le funzioni predefinite.
** PUSH "dummy"                              ; [dummy,...]
** valuta arg1; PUSHA                       ; [arg1,dummy,...]
** ...
** valuta argN; PUSHA                       ; [argN,...,arg1,dummy,...]
** PUSH arity
** CALL entrypoint
// CALL consuma arity, sostituisce dummy con PC+1 e salta:
// [argN,...,arg1,return,...]
// RET elimina return dopo che il callee ha portato SP sotto gli argomenti.
// A attraversa CALL/RET ed e' il valore restituito.
// Una predefinita priva di traduzione SQL provoca errore di compilazione
// quando viene incontrata con sql_mode=1.
startparallel=
    // Task e target ricevono i parametri esattamente come una funzione:
    // controllo statico dell'arita', valutazione da sinistra a destra e frame
    // [argN,...,arg1,return,...]. Cambia soltanto chi avvia la nuova VM e come
    // le passa il frame serializzato; non cambia l'ingresso del corpo.
    // Non esiste un secondo formato di stato: ASK, task e target usano lo
    // stesso serializzatore gia' esistente, che trasforma stack e posizione
    // nello stesso stringone ripristinabile dalla nuova VM.
    cron nometask(parametri) modocrontab   //"30 * * * *" parametri passati per valore
    // La pianificazione e' persistente lato server.
    // La politica di pulizia dei cron non e' ancora definita.
    // Il nome del target identifica il cron: una nuova dichiarazione dello
    // stesso target sostituisce pianificazione e parametri precedenti.
    **push nometask
    **per tutti i i parametri
    **- inexp() 
    **- push parametro
    **push arity
    **inexp()
    **PUSHA
    **CRONTASK arity
    refresh nometarget(parametri), interval
    // interval e' obbligatorio e strettamente positivo, in millisecondi;
    // a ogni scadenza richiama il target
    // con una nuova copia dei parametri per valore.
    // Se alla scadenza il task e' running, la nuova esecuzione non parte.
    ** PUSH "nometarget"
    ** valuta parametro1; PUSHA
    ** ...
    ** valuta parametroN; PUSHA
    ** PUSH arity
    ** valuta interval; PUSHA
    ** REFRESHTARGET entrypoint
    // L'argomento intero dell'opcode e' l'entrypoint risolto staticamente.
    // REFRESHTARGET consuma intervallo, arita', parametri e nome; conserva lo
    // stesso stringone dello stack usato da ASK insieme ai parametri necessari
    // a costruire il frame della nuova VM. Un nuovo refresh dello stesso nome
    // target sostituisce il precedente.
    (NO) run nometask(parametri)
    // Estensione facoltativa: accoda una singola esecuzione nel gestore
    // esterno. Non usa CALL e non esegue il task nel flusso corrente.
    // EWB sopravvive anche senza questa forma: oggi i task partono da CRON.
    run nometarget(parametri)
    // Il compilatore riconosce staticamente che il simbolo e' un target.
    // Genera un form invisibile contenente parametri, stack, entrypoint,
    // stackpos e firma; emette poi JavaScript che lo invia una sola volta via
    // AJAX. Il flusso corrente prosegue senza attendere il risultato.
    // Anche il target viene quindi eseguito da una nuova VM, non tramite CALL.
    ** PUSH "nometarget"
    ** valuta parametro1; PUSHA
    ** ...
    ** valuta parametroN; PUSHA
    ** PUSH arity
    ** RUNTARGET entrypoint

//qui mi complico la vita, ma almeno posso definire i numeri in qualunque base e dimensione.. 
  numvalue = [+/-] ( bin | hex | oct | dec ) 
  bin = 0b [0..1] [. {0..1} ]
  oct = 0o [0..7] [. {0..7} ]
  hex = 0x ([0..1]|[A..F]|[a..f])  [. {([0..1]|[A..F]|[a..f])} ]
  dec = [0..9] [. {0..9} ]
  // La parte frazionaria e' ammessa in tutte le basi.
  // La notazione esponenziale non fa ancora parte della sintassi.
  ** MOVA "testo numerico"
  ** con sql_mode: PUSHA; SQLNUMBER
  strvalue = \" carattere \"
  ** MOVA "testo"
  ** con sql_mode: PUSHA; SQLQUOTE
token= a..z|A..Z | _  [a..z | A..Z | 0..9 | _ ]
// Operatori e primitive numeriche validano l'intera stringa secondo numvalue;
// una conversione parziale provoca RAISE.
// JZ/JNZ e operatori logici: sono falsi "" e ogni numvalue uguale a zero;
// ogni altra stringa non vuota e' vera.
// Per le strutture: array senza chiavi falso, con almeno una chiave vero.
// Operatori logici e confronti lasciano sempre in A "0" oppure "1".

'il valore rimosso; se la chiave e' assente restituisce "".
'Su scalare non vuoto provoca RAISE; su "" restituisce "".
	** PUSH "nomevariabile"; valuta chiave; PUSHA; DELKEY
'Su "" NUMEL e NUMKEY valgono 0; su ogni altro scalare provocano RAISE.

Per l' uso di sock stream

Ho la necessita' di comunicare con altri programmi con sock stream o a pacchetto...
Cerco di fare la cosa nel modo piu' spiccio possibile.
Le sock sono handle opachi della VM.

	socket(host, port)
	** valuta host; PUSHA; valuta port; PUSHA; SOCKET
	// Apre una socket client TCP IPv4 e attiva autoflush.
	// Se risoluzione o connessione falliscono restituisce falso/vuoto.

	server(port)
	** valuta port; PUSHA; SERVER
	// Apre una socket TCP IPv4 in ascolto, backlog 5 e riuso indirizzo.
	// Se l'apertura fallisce restituisce falso/vuoto.

	accept(server_socket)
	** valuta server_socket; PUSHA; ACCEPT
	// Attende una connessione e restituisce la socket client con autoflush.
	// La chiamata e' bloccante; se fallisce restituisce falso/vuoto.

	sread(socket)
	** valuta socket; PUSHA; SREAD
	// Legge una riga. Come nel runtime storico, conserva il newline ricevuto.
	// EOF o errore restituiscono falso/vuoto.

	swrite(socket, dati)
	** valuta socket; PUSHA; valuta dati; PUSHA; SWRITE
	// Scrive i dati esattamente come sono, senza aggiungere newline.
	// Restituisce l'esito storico della scrittura: vero se riuscita, falso
	// altrimenti; non il numero dei byte.

	close(socket)
	** valuta socket; PUSHA; SCLOSE
	// Chiude la socket e restituisce vero o falso.

// Le socket sono risorse vive del processo e non sono serializzabili. La regola
// e' generale: qualsiasi risorsa viva della VM che non possa essere ricostruita
// dal valore serializzato provoca RAISE se compare nello stato da trasferire,
// in A, nello stack o in una variabile. Vale per ASK e per l'avvio esterno di
// task e target, che usano lo stesso stringone dello stack. La VM non converte
// un handle in testo e non tenta di ricostruirlo alla ripresa.

	(NO) read(port)
	(NO) write(host, port, dati)
	// Primitive datagram presenti nella sintassi, ma non ritrovate nel runtime
	// storico disponibile (circa 5.30). Blocco, timeout, risultato ed errori
	// restano da definire; non si deducono dalle socket TCP.

Per uso di minmax e euristiche ? 

Formato base, vicino al vecchio motore:

  dataset pianificazione = 
  { [ nomeregola/nomefatto {= regola} ] 
    fatto(...),
    fatto(...),
    regola(...) :- condizioni(...)
  }
  
  Estensione euristica minima:

  goal pianificazione, soluzione max score {
    ...
  }

  Dove score può essere:

  - una variabile prodotta dalla regola;
  - una funzione;
  - una calcexp valutata sulle variabili del goal.

  Esempio più semplice:

  dataset assegnazioni = {
    tecnico("Marco","VR","radio",3),
    tecnico("Luca","VI","radio",1),
    tecnico("Anna","VR","radio",2),

    adatto(Nome,Zona,Skill,Carico) :-
      tecnico(Nome,Zona,Skill,Carico),
      Zona == "VR",
      Skill == "radio"
  }

  goal assegnazioni, adatto(Nome,Zona,Skill,Carico) min Carico {
    print Nome
  }

Target: unità logica di presentazione, indipendente dal renderer. Potenziale base per aggiornamenti AJAX, rendering parziale e future interfacce non HTML.

    }

    }

Ipotesi:
Task e Target sono la stessa cosa.

Problema:
Si confondono esecuzione e presentazione.

Decisione:
Il Target estende il Task, ma i due concetti restano distinti.

Io la vedrei quasi così (in termini OO, anche se poi la VM non sarà OO):

              Executable
                  │
        ┌─────────┴─────────┐
        │                   │
      Task              Target

Dove Executable definisce:

contesto
parametri
stato
trigger
logging
timeout
lock
gestione errori

Il Task aggiunge:

cron
unique
ready/error
result

Il Target aggiunge:

renderer
id/class
ajax
refresh
eventi UI

Quindi il runtime vede sempre un oggetto eseguibile.

Per esempio.

task generaStatistiche
{
    ...
}

e

target statistiche ajax every "30s"
{
    ...
}

internamente sono quasi identici.

Il secondo diventa:

Task
    |
    +-- Renderer HTML
    +-- Trigger AJAX
    +-- Target ID

Questo porta ad una conseguenza interessante.

Un target potrebbe essere lanciato anche senza browser.

Ad esempio:

render(statistiche,"pdf");

oppure

render(statistiche,"json");

Perché il target non è HTML.

È una funzione che produce una vista.

HTML è solo uno dei renderer.

Ed ecco una cosa che mi è venuta in mente adesso.

Se i target sono "task con renderer", allora potrebbero avere cache.

target dashboard
cache 30s
{
    ...
}

Il runtime dice:

"L'ho già calcolato 12 secondi fa."

e restituisce direttamente il rendering.

Oppure:

target mappa
invalidate on comuni
{
    ...
}
